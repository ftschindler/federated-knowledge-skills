# 0.1.0 - the workspace starts saying what release it is on

**What changed.** Nothing about how bundles work, and nothing in any of them. `fkb` now
carries a release number, and the workspace manifest records which release it was last
brought up to. Before this, a skill that had been upgraded had no way to tell that the setup
on the machine predated it, so a change that needed a decision - a new manifest field, a new
command worth adopting - arrived silently and was never put to anybody.

This guide is the first link of that chain, and it exists so the chain is walked once while
there is nothing at stake.

**What to do.**

1. Run `fkb version`. It prints the release this installed copy is, where it is installed,
   and what the workspace stands at - `unstamped` for every setup made before now.
2. Tell the person, in one line, that from now on `fkb list` will say when an upgraded skill
   needs something of their setup, and that nothing is being changed today.
3. Run `fkb migrate --done`. That writes `version: 0.1.0` into
   `$XDG_CONFIG_HOME/fkb/workspace.yaml`, under the comment block at the top.

**If they decline.** There is nothing to decline - no policy changes and no file of theirs is
touched. If they would rather not have the field written, leave it: everything keeps working
exactly as it did, and `fkb list` will carry the notice until it is recorded.

**How to tell it worked.** `fkb version` names the same release on both lines, and `fkb list`
opens with the bundles rather than with a notice.
