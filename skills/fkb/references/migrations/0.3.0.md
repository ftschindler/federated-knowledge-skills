# 0.3.0 - the rule is subscribed to rather than pasted in

**What changed.** The five lines that make a session reach for the bundles at all used to be
text in `references/agents-block.md`, copied by hand into whichever file the harness loads
before every message. Those lines now live at `rules/fkb.md` in the project's repository,
which is the only copy of them anywhere, and
[`akit`](https://github.com/ftschindler/federated-agent-kits) renders them into that file
and keeps them current.

A copy pasted by hand is one no release can reach: it stays as it was written while the
wording here moves on, and neither half knows about the other. Subscribing replaces that
with a rendered block an upgrade carries, alongside the skill, under one name.

This is a new capability. A setup with the block pasted in works exactly as it did, and the
last step below is worth doing whether or not they subscribe.

**What to do.**

1. **Say what is on offer, then ask.** One command subscribes to the skill and the rule
   together and renders both:

   ```sh
   uvx --from federated-agent-kits akit add --global ftschindler/federated-knowledge-skills fkb
   ```

   Ask before running it. It writes into the file that loads on every session they run, for
   every project, and it starts a manifest of subscriptions they did not ask for. Everywhere
   else this skill runs the command it proposes, because what it writes is a bundle somebody
   asked for; this one is a change to how every future session behaves.

   `akit` needs `uv`, which the `fkb` CLI needs anyway. Where they say no, go to step 4: it
   is the only step that matters either way.

2. **Lift their own lines out of the old block before touching it.** This is the step that
   quietly loses something. A block that has been in place for a while usually carries a line
   nobody else would have written - "my notes" mapped to the `private` bundle, a phrase they
   use for an upstream, a bundle name only they say out loud. Read the old block with them
   and move anything of theirs into their own part of the file, above or below the rendered
   one and **outside** the `<!-- BEGIN akit fkb -->` markers. A rendered rule is rewritten
   whole on every render, so a line left inside those markers survives until the next one and
   then is gone without a message.

3. **Then delete the hand-pasted block.** The rendered one now says the same thing, and
   leaving both means two sections about knowledge bundles in one file, with nothing to
   choose between them. Do this only once the rendered block is actually in the file; `akit
   list` says where it was written.

4. **Delete the stale files in the installed skill directory**, whether or not they
   subscribed:

   - `references/agents-block.md`, which this release replaces with
     `references/reachability.md`. It holds the old copy of the block and nothing links to it
     any more.
   - any `__pycache__` directory under `scripts/`, left by an earlier copy running the CLI.

   **Nothing else will do this.** An upgrade replaces the files a release changed and does
   not remove the ones it deleted - that is true of `akit`, which only touches files it
   wrote, and of copying the new `skills/fkb/` over the old one. `akit doctor` stays silent
   about them for the same reason. A stale `agents-block.md` is a second copy of the very
   text this release removed, which is what makes it worth a step of its own.

**If they decline.** Nothing breaks and nothing is lost. A pasted block keeps working for as
long as it sits there, and the skill, the CLI and the hooks never ask whether `akit` is
present. What they give up is upgrades: the next time the rule's wording improves, a
subscribed copy follows and a pasted one does not. They can subscribe any day, and step 4 is
still worth doing today.

**How to tell it worked.** `uvx --from federated-agent-kits akit list` names `fkb` twice,
once as a skill and once as a rule, and says which files each landed in. The instructions
file holds the block exactly once, between the `akit` markers, with anything of theirs above
or below it. And `references/agents-block.md` is gone from the skill directory.
